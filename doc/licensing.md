# Licensing

`offline_translate` is meant to be usable inside commercial applications. That
constraint shaped the model choice more than performance did. This page records
what each piece is licensed under and what an application shipping it has to do.

**This is a summary of what was checked, not legal advice.** Have your own
counsel confirm anything that matters to you.

## 2. Runtime dependencies

| Dependency | License | Notes |
|---|---|---|
| ONNX Runtime 1.29.0 | MIT | Microsoft; Android via the official AAR, Apple via the `onnxruntime-c` pod |
| `ffi` | BSD-3-Clause | Dart team |
| `path`, `path_provider`, `http`, `crypto`, `meta` | BSD-3-Clause | Dart team |
| Flutter, Dart | BSD-3-Clause | |

The FFI bindings in `lib/src/engine/native/onnx_runtime_bindings.dart` are
generated by `ffigen` from ONNX Runtime's own MIT-licensed headers, so they
carry ONNX Runtime's copyright. That is compatible with this package's MIT
license and with commercial redistribution; ship ONNX Runtime's MIT notice with
your application either way.

Every runtime dependency is permissive. There is no copyleft anywhere in the
chain, and nothing requires source disclosure.

Shipping ONNX Runtime means shipping its **third-party notices**, reproduced in
ONNX Runtime's own `ThirdPartyNotices.txt`.

### 2.1 What this package deliberately does not ship

The official ONNX Runtime **Android AAR** contributes an
`ai.onnxruntime.TelemetryInitializer` `ContentProvider`, plus `INTERNET` and
`ACCESS_NETWORK_STATE` permissions, to the manifest of every application that
depends on it. A `ContentProvider` is instantiated at application start, and
that one builds an HTTP client.

This package does not use the AAR as a Gradle dependency. It extracts
`libonnxruntime.so` from it and nothing else, so no telemetry component,
permission or Java class reaches your application. `doc/onnx-runtime.md` §2.1
shows the mechanism and the verification on a built APK.

## 4. The default models: Firefox Translations, MPL-2.0

The models this package ships by default come from
[mozilla/firefox-translations-models](https://github.com/mozilla/firefox-translations-models),
under the **Mozilla Public License 2.0**. This is the only copyleft licence
anywhere in the stack, so it is worth being precise about what it does and does
not reach.

| | |
|---|---|
| Licence | MPL-2.0 |
| Commercial use | **yes**, without restriction |
| Attribution | required |
| Copyleft scope | **per file**, and only files that are MPL-licensed or derived from them |

**Using the models does not make your application MPL-2.0.** MPL-2.0 §1.10 and
§3.3 attach the obligation to "Covered Software" — the licensed files and their
modifications — not to a larger work that merely combines with them. Your
application code, and this package, keep their own licences. This is the whole
practical difference between MPL and the GPL family, and it is why MPL-2.0 was
acceptable here where CC-BY-NC was not.

**Redistributing the converted bundles does carry an obligation.** The ONNX
files `tool/build_tiny_model.py` produces are derived from MPL-2.0 files, so:

* keep them under MPL-2.0;
* make the **source form** available to recipients. In practice this means
  pointing at the upstream checkpoint and at `tool/build_tiny_model.py`,
  `tool/marian_binary.py` and `tool/tiny_transformer.py` — together they are the
  complete recipe from the published Marian binary to the shipped bundle;
* keep the licence notice. Each bundle's `manifest.json` records
  `"license": "MPL-2.0"` and its `base_model`, and `ModelInfo.license` exposes
  both to the application, so a credits screen can read them at runtime rather
  than hard-coding them.

If MPL-2.0 is unacceptable in your context, `tool/build_model.py` builds
Apache-2.0 OPUS-MT bundles that this package runs equally well — larger and
slower, but permissive. See
[model-decision.md](model-decision.md) for what that trade costs.

## 5. The OPUS-MT models — the alternative

Model weights are **not** covered by this package's license. Each bundle carries
its upstream license in `manifest.json`, and you inherit that license when you
distribute the bundle.

### 4.1 What was rejected, and why

| Model | License | Verdict |
|---|---|---|
| `facebook/nllb-200-distilled-600M` | **CC-BY-NC-4.0** | **rejected — non-commercial** |
| `facebook/m2m100_418M` | **CC-BY-NC-4.0** | **rejected — non-commercial** |
| `facebook/mbart-large-50-*` | MIT code, CC-BY-NC training data | rejected — ambiguous provenance |
| `google/gemma-3-270m` | Gemma Terms of Use | rejected — use restrictions, not OSI |

NLLB is the model most on-device translation write-ups reach for, and it cannot
be shipped in a commercial app. That single fact removed it from consideration
before any benchmark was run. Verify it yourself:

```console
$ curl -s https://huggingface.co/api/models/facebook/nllb-200-distilled-600M \
    | jq .cardData.license
"cc-by-nc-4.0"
```

### 4.2 What was chosen

**OPUS-MT / Helsinki-NLP**, one checkpoint per direction. Eleven of the twelve
V1 directions are **Apache-2.0**; `en-de` is **CC-BY-4.0**.

| Direction | License | Redistribution | Commercial | Attribution |
|---|---|---|---|---|
| en→fr, fr→en, en→es, es→en, de→en, fr→es, es→fr, fr→de, de→fr, es→de, de→es | Apache-2.0 | yes | yes | notice only |
| **en→de** | **CC-BY-4.0** | yes | yes | **credit required** |

Both licenses permit redistribution of *modified* weights, which is what
quantisation and the ONNX conversion produce. Apache-2.0 §4 requires carrying
the license and a NOTICE of modifications; CC-BY-4.0 §3(a) requires crediting
the creator, linking the license, and indicating that changes were made.

### 4.3 What your application must do

If you ship any bundle:

1. Include the upstream license text with your app's third-party notices —
   Apache-2.0 for most directions, CC-BY-4.0 for `en-de`.
2. State that the weights were **modified** (quantised to int8, converted to
   ONNX, and given an extra `next_token` graph output).
3. Credit the OPUS-MT project.

A notice that satisfies all three:

```text
Translation models: OPUS-MT (Helsinki-NLP), https://github.com/Helsinki-NLP/Opus-MT
Licensed under Apache-2.0, except en→de which is licensed under CC-BY-4.0.
Modified: converted to ONNX, dynamically quantised to int8, and extended with a
greedy arg-max output node.

Citation:
  Jörg Tiedemann and Santhosh Thottingal. OPUS-MT — Building open translation
  services for the World. EAMT 2020, Lisbon, Portugal.
```

`ModelInfo.license` and `ModelInfo.baseModel` carry this per installed model, so
an app can generate the notice from what is actually installed:

```dart
for (final model in await translator.installedModels()) {
  print('${model.id}: ${model.baseModel} (${model.license})');
}
```

### 4.4 Training data

OPUS-MT is trained on the OPUS corpora, which aggregate many sources under
varying terms. The Helsinki-NLP checkpoints are published under the licenses
above and that is what governs their redistribution. If your jurisdiction or
your customers require provenance guarantees about training data, that is a
question for the upstream project, not for this package — and it applies equally
to every published NMT model.

## 6. Data privacy

Nothing here is a licensing question, but it is usually asked in the same
breath: after installation, translation makes **no network calls of any kind** —
no HTTP, no DNS, no telemetry. Text never leaves the device. The only code in
this package that opens a socket is `HttpModelSource`, and it is only reachable
through `installModel()`.

This is asserted by tests rather than merely claimed:

* `example/integration_test/translation_test.dart` runs a translation inside an
  `HttpOverrides` zone where creating an HTTP client throws.
* `tool/offline_proof.sh` installs a model, switches Wi-Fi and mobile data off,
  removes the adb tunnel, stops the host server, relaunches the app, and asserts
  that it still translates and reports `online=false`.
